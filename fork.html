What this fork adds

These docs cover brunokrugel/crush, a fork that tracks charmbracelet/crush upstream and carries a curated set of changes on top: upstream pull requests that are still open there, plus feature branches from other forks. This page is the inventory of what it adds beyond upstream main.

How this fork is built

None of the additions below are bespoke. They are merges of upstream pull requests (numbered as such) and of published feature branches, each pullable into the fork branch with two commands. When upstream eventually merges its own copy of these changes, the duplicate history drops out cleanly.

Credits​

The work in this fork is not the work of one person. It is pulled from upstream pull requests and from the other Crush forks, all landing on the same branch and improving each other there. Every row in the tables below names the source it came from; this is the summary.

SourceWhat it contributed
brunokrugel/crushThis fork. The integration work, the snapshots implementation, the Sonic JSON codec, and the merged upstream pull requests.
joestump-agent/crushMulti-agent dispatch, semantic search, channel reply routing, and most of the TUI polish — click-to-copy, clickable links, the highlighted composer, text attachments, and the Skills, MCP and Channels dialogs.
taigrr/crushConversation forking, goal mode, and the original snapshot design this fork reimplemented.
gurnben/crushContext compaction with checkpoints, via its feat/context-compaction branch.
charmbracelet/crushUpstream. Everything the fork does not change, and the pull requests merged in ahead of upstream merging them itself.

Major features​

FeatureWhat it isSource
Scheduled tasksCronCreate, CronList, and CronDelete tools that re-run a prompt on a cron schedule, with a scheduler, one-shot support, and a command-palette entry showing what is queued.upstream PR #3466
MemoryCross-session memory via Honcho: Crush sends turns, completed replies, and redacted tool summaries, and later sessions get recall back. Connect or disconnect from the command palette or crush login honcho; sub-agents read memory but never write it. Off by default and free when off; this fork targets a self-hosted instance.upstream PR #3954 (draft)
ForkingBranch a conversation from any message into a new session that keeps the history up to that point, with the snapshot's files restored in place or in a fresh worktree. The source session is left untouched. Fork from the palette (at the last prompt) or press f on a user message in the transcript to fork at that exact point; remote clients fork through POST /v1/workspaces/{id}/sessions/{sid}/fork.taigrr/crush (reimplemented)
SnapshotsA git-backed filesystem checkpoint captured in the background at every user message into a private store under .crush/git — browse them in the Snapshots palette entry, restore any point (the current tree is captured first, so a restore is itself undoable), copy a snapshot's diff, and bound how many a session keeps with snapshots.keep, with .gitignore and exclusion support and content-addressed reuse so unchanged files cost nothing.brunokrugel/crush, after taigrr/crush
Goal mode/goal <text> starts an autonomous, turn-budgeted loop on the current session: after each turn a cheap small-model evaluator checks whether the goal is met, and while it is not — and the budget (25 turns, hard-capped) allows — a continuation directive is injected and another turn runs. It reuses the fork's todo-nudge ladder and its watchdogs instead of adding a second enforcement layer, and the continuation supersedes the nudge so a turn never gets two injections. An active goal shows as a GOAL badge (with the turn budget) in the header.taigrr/crush (reimplemented; PLAN.md #5)
Auto modeAn opt-in safety classifier that grants, denies, or escalates a tool call that would otherwise prompt. User-level only: a repository cannot grant itself auto mode. No classifier model means rules-only. A classifier error escalates.gurnben/crush, upstream PR #3874
Context compaction with checkpointsAutomatic compaction ledgers for long-running sessions, with preview/accept/discard checkpoints, an undo path, and inline checkpoint handoff in the TUI; recorded session memory rides beside every summary instead of replacing it, and the checkpoint accepts an emphasis instruction.gurnben/crush:feat/context-compaction, upstream PR #4059 (28 commits)
Multi-agent dispatchA dispatch_agent tool that starts independent agents in the background, each in its own git worktree on a fresh crush-dispatch-* branch, while the main agent keeps working. Steer a running agent with a leading @handle (the model uses message_agent), read its live transcript in inspect mode, cancel it with ctrl+x or cancel_dispatch, and settle its work with apply_dispatch (merge, squash or cherry-pick) or dismiss_dispatch — Crush never merges on its own. Every agent is an agent definition: override coder, plan, task and worker or add your own with the agent builtin in crushrc. crush dispatch list and prune manage workspaces from the shell. On by default inside a git repository.joestump-agent/crush
Semantic searchA local vector index over the repo — chunked by symbol, embedded through any OpenAI-compatible endpoint, stored in the project's own SQLite via sqlite-vec. Adds the semantic_search and semantic_index tools and a symbol-extraction package.joestump-agent/crush
Channel reply routingThe channel push mechanism is upstream. This fork adds the channel_enabled config key, a channel_reply tool, server-side routing that delivers each event exactly once per workspace, auto-creation of a session for an inbound event, and replies that go back only to the channel they came from.joestump-agent/crush
Herdr compatOverhauled agent state reporting and pane integration for the herdr multiplexer, including compaction state reporting.upstream PR #3541
Lazy MCP loadingMCP tool schemas stay out of the model's context until explicitly pulled with mcp_search; per-server tri-state settings in the MCP dialog, plus list_mcp_prompts and call_mcp_prompt tools and prompts offered in the inline / completions.upstream PR #3983, brunokrugel/crush
Skill scoping and cachingDeduplicated symlinked skills, skill discovery cached across prompt builds, repo-scoped enable/disable toggles over the global config.upstream PRs #3830, #3813, plus the skill-toggle upstream work
Session-scoped promptsPermission and question prompts are scoped to the session the client is actually viewing: clients report their current session, pending prompts re-publish when a client switches to the session that raised them, and sub-agent prompts surface on the top-level session.upstream PRs #4044, brunokrugel/crush
Turn and paste UXThe turn spinner runs from the moment a prompt is sent (not when the first assistant message lands), a setup failure still publishes RunComplete, copied file paths paste as text rather than attaching, and ctrl+shift+v pastes the clipboard as text on every model.upstream PRs #4046, #4070, #4071, brunokrugel/crush

Performance​

ImprovementDetailSource
Sonic JSON codecBoth halves of the JSON wire path run through bytedance/sonic's JIT-compiled codec: every Unmarshal/Marshal call in the tree, plus the HTTP handlers (server, A2A, proto), the CLI's session output, and the streaming message deltas and session-row decodes. encoding/json remains only where sonic has no equivalent (RawMessage, the Marshaler/Unmarshaler interfaces sonic dispatches through, and streaming decode).brunokrugel/crush

Fixes this fork carries​

Fixes to upstream behaviour that live here and are not upstream. Fixes to the fork's own features are part of those features and are not listed separately.

FixSymptom it removes
Forked child output tears the TUIOn macOS under memory pressure, the malloc stack logger prints into the fork-to-exec window of every forked child, corrupting the TUI. fd 2 is detached to /dev/null while the TUI runs; Go's stderr and crash reports keep the terminal.
Quitting abandons work in flightClosing the terminal window or stopping the server through a service manager killed the process outright: active runs never wound down, and the next visit to the session showed a step that still looked like it was running. External stop signals now go through the ordinary workspace shutdown, so runs record their terminal state, and a shutdown while work is genuinely still running says so in the log.
Cancelled turn streams keep runningCancelling a turn left the provider stream running to its natural end whenever the request timeout was off, and a turn whose stream only ever sent keepalives ran until the (disabled) timeout. Cancelling now stops the stream immediately even with the timeout off, a keepalive-only stream ends at the stall budget, and a cancelled turn finishes cleanly.
Oversized images rejected by the providerA screenshot past the provider's per-image limits failed the whole request. Oversized images are now rescaled into the limits instead.
Yolo banner inverted when truncatedThe allow-all-permissions banner led with "runs any commands…", so a cut banner read as the opposite of the truth. It now leads with the limit, so a cut banner still says the safe thing.
Todo pill frozen on a stale stepThe todo ladder treated creating a todo list as lifetime activity, so a model that made the list and then worked on later steps without updating it left the todo pill on the first step for the whole run. Mutating work now makes the list stale and re-arms the reminder, while read-only calls leave its freshness alone.
Bounded MCP init waitsA wedged MCP server could blank the whole app at startup. Tool lists now wait for init, with a bound.
Per-server MCP lifecycle serializedConcurrent connect/disconnect on one server raced; an error on one session tore down others.
stdio process groups reapedKilled stdio MCP servers left orphan processes behind.
MCP OAuth persistenceTokens did not actually survive a restart; the store now does atomic writes and validates state.
In-process run dispatch serializedTwo turns could run concurrently in one session.
Provider base URL resolved before validationA custom provider with an expanded base_url failed validation that should have passed.
Empty paste routes to the clipboard imageAn empty bracketed paste dropped the image instead of attaching it — and now warns instead of silently failing on a model that cannot take images.
Command filter matches shortcutsTyping a command's shortcut in the / menu filtered it out.
Tied project timestamps ordered by recencyProjects registered in the same instant sorted arbitrarily.
Backspace in the commands filterBackspace was swallowed in the top-level commands filter.
Sub-agent permissionsNon-interactive permission propagation applied only to the main agent, so a subagent's runs prompted from scratch.
Sentry known-sessionlesshttps://mcp.sentry.dev/mcp ships pre-registered in knownSessionlessMCPs; known sessionless servers skip the subscriptions stream that stalls them.

What this fork does NOT have​

Anything not in the table above is plain upstream Crush or one of the merged branches named above. In particular A2UI was removed entirely — the earlier brunokrugel/crush A2UI plumbing is gone: no a2tea dependency, no renderer for cards, lists, buttons, forms, or dashboards drawn inline, no prompt section inviting surfaces, no disable_a2ui config option, and no MCP capability advertisement. Inline <a2ui-json> blocks in a reply render as plain text.
